## §3 Blocker B — Q3 Negative-Evidence Semantics (PASS)

The orchestrator's Q3 scoring logic was refactored to use bounded
negative-evidence semantics per RA2 §3 / §5. The decision tree:

| Condition | Q3 Status |
|---|---|
| positive_recall_adequate AND recovered DOI == Scheffer 2020 | LIKELY_CONFLATION |
| positive_recall_adequate AND recovered DOI is None | PENDING_NEGATIVE_COVERAGE_RULE |
| positive_recall_adequate AND recovered DOI is unrelated | PENDING_NEGATIVE_COVERAGE_RULE (no overclaim) |
| NOT positive_recall_adequate | COVERAGE_INSUFFICIENT |

The key fix: `if NOT positive_recall_adequate: COVERAGE_INSUFFICIENT`
regardless of what the negative query returned. The previous RA1
overclaim (arbitrary wrong DOI -> LIKELY_CONFLATION) is no longer
reachable. The "ELSE" branch in the original §5 pseudocode that
produced arbitrary LIKELY_CONFLATION is replaced with
`PENDING_NEGATIVE_COVERAGE_RULE` (a future-capability placeholder
that does NOT assert strong negative evidence).

Verified by 3 tests:
- `test_ra2_03_scheffer_2020_recovery_produces_likely_conflation`:
  positive_recall_adequate=True, recovered=10.7554/eLife.57443 ->
  LIKELY_CONFLATION
- `test_ra2_04_unrelated_wrong_doi_does_not_produce_likely_conflation`:
  positive_recall_adequate=True, recovered=10.1234/unrelated ->
  PENDING_NEGATIVE_COVERAGE_RULE (NOT LIKELY_CONFLATION)
- `test_ra2_05_inadequate_positive_recall_returns_coverage_insufficient`:
  positive_recall_adequate=False, recovered=10.7554/eLife.57443 ->
  COVERAGE_INSUFFICIENT (regardless of DOI)
